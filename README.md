# lab02_ab-320_sychuk

Лабораторная работа №2: классификация подозрительных событий аутентификации.

**Вариант 3 (№21 в списке).** Фокусные поля: `timestamp`, `hour`, `is_weekend`, `device_type`, `os_family`, `browser_family`, `known_device`. Основная проверка - временное разделение по `timestamp`.

## Задача

Построить учебный классификатор подозрительных попыток входа, сравнить несколько методов на одном протоколе и выбрать модель с порогом при ограниченной емкости ручной проверки. Целевая переменная `is_suspicious`: `0` - нормальное событие, `1` - подозрительное. Результат предназначен для аналитика SOC: приоритизация проверок при ограниченном лимите алертов.

## Текущий этап

Реализован этап 1 - подготовка данных. Ноутбук содержит только необходимые шаги:

- загрузка датасета и сохранение `source_row_id`;
- очистка по правилам ЛР №1 и приведение типов;
- заполнение `distance_from_usual_km` и `password_age_days` медианой, `browser_family` и `department` - категорией `Other`;
- если после медианного заполнения `password_age_days > account_age_days`, значение `password_age_days` заменяется на `account_age_days`; затем проверяется, что таких строк не осталось;
- удаление полных дубликатов по исходным полям, без `source_row_id`;
- распределение целевой переменной и формирование `X`, `y`;
- создание нового необученного конвейера с `SimpleImputer(strategy='median')`, `RobustScaler` и `OneHotEncoder`.

Медианное заполнение пропусков выполняется при очистке строк, как в ЛР №1. Дополнительно медианный imputer остается внутри конвейера: `fit` будет выполнен только на train. Внешний test из ЛР №1 и validation на этом этапе не выделены. Это следующий шаг: test воспроизводится без изменений, а validation выделяется только из прежнего train до обучения любых преобразований.

Исходные данные в `data` не изменяются. В X не входят `event_id`, `timestamp`, `user_id`, `source_ip`, `analyst_verdict`, `analyst_risk_score` и `source_row_id`.
